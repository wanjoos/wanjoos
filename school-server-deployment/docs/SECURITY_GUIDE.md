# 🔒 보안 담당자용 - 시스템 검토 가이드

## 시스템 개요

### 프로그램명
**KSA 야간자습 출석체크 시스템**

### 용도
교사가 스마트폰/태블릿으로 야간자습 출석을 체크하는 웹 기반 애플리케이션

---

## 기술 스택 및 아키텍처

### 1. 기술 구성
```
프론트엔드: React.js v18 (JavaScript 라이브러리)
백엔드: Node.js v20 + Express.js v4
데이터 저장: JSON 파일 (로컬 파일 시스템)
프로토콜: HTTP (HTTPS 권장)
```

### 2. 시스템 아키텍처
```
┌─────────────────────────────────────────┐
│         교사 디바이스 (브라우저)          │
│      스마트폰 / 태블릿 / PC             │
└──────────────┬──────────────────────────┘
               │ HTTP/HTTPS
               │ (학교 내부망)
┌──────────────▼──────────────────────────┐
│         학교 내부 서버                    │
│  ┌────────────────────────────────────┐ │
│  │   Frontend (React.js)              │ │
│  │   Port: 80 또는 5173               │ │
│  └────────────┬───────────────────────┘ │
│               │                          │
│  ┌────────────▼───────────────────────┐ │
│  │   Backend (Node.js + Express)      │ │
│  │   Port: 3001                       │ │
│  └────────────┬───────────────────────┘ │
│               │                          │
│  ┌────────────▼───────────────────────┐ │
│  │   Data Files (JSON)                │ │
│  │   - students.json (학생 명단)      │ │
│  │   - attendance.json (출석 기록)    │ │
│  │   - pre_absence.json (공결 정보)   │ │
│  └────────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

## 보안 특징

### ✅ 개인정보 보호
1. **완전 내부망 운영**
   - 모든 데이터가 학교 서버 내부에만 저장
   - 외부 클라우드 서비스 사용 안 함
   - 외부 API 호출 없음

2. **데이터 저장 위치**
   ```
   /attendance-system/students.json       (학생 명단)
   /attendance-system/backend/data/attendance.json  (출석 기록)
   /attendance-system/backend/data/pre_absence.json (공결 정보)
   ```

3. **수집 정보**
   - 학생: 학번, 이름, 학년, 자습실
   - 출석: 날짜, 시간, 상태(출석/결석/공결)
   - **수집하지 않는 정보**: 주민번호, 연락처, 주소 등

### ✅ 접근 통제
1. **인증**
   - 비밀번호 기반 세션 인증
   - 세션 정보는 브라우저 sessionStorage에 저장 (서버 재시작 시 재로그인 필요)

2. **권한**
   - 교사만 접근 가능 (비밀번호 보유자)
   - 학생은 접근 불가

3. **네트워크 제한** (선택적 설정 가능)
   - 학교 내부 IP 대역만 접근 허용
   - 외부 인터넷에서 접근 차단

## 취약점 점검 체크리스트

### 1. 주요 웹 취약점

| 취약점 | 위험도 | 현황 | 비고 |
|--------|--------|------|------|
| SQL Injection | 없음 | ✅ 안전 | 데이터베이스 미사용, JSON 파일 사용 |
| XSS (Cross-Site Scripting) | 낮음 | ✅ 방어됨 | React의 자동 이스케이프 처리 |
| CSRF (Cross-Site Request Forgery) | 낮음 | ✅ 방어됨 | Same-Origin 정책 적용 |
| Path Traversal | 낮음 | ✅ 방어됨 | path.join() 사용, 정적 경로만 접근 |
| 인증 우회 | 중간 | ⚠️ 주의 | 세션 기반 인증, HTTPS 사용 권장 |
| 무차별 대입 공격 | 중간 | ⚠️ 주의 | Rate limiting 미구현 (필요시 추가 가능) |

### 2. 보안 권장사항

#### 필수 사항:
- ✅ **방화벽 설정**: 학교 내부망 IP만 접근 허용
- ✅ **HTTPS 적용**: SSL/TLS 인증서 설치 (자체 서명 또는 Let's Encrypt)
- ✅ **정기 백업**: 데이터 파일 일일 백업
- ✅ **로그 모니터링**: 접근 로그 정기 확인

#### 선택 사항:
- ⭐ **Rate Limiting**: 로그인 시도 횟수 제한 (Express-rate-limit)
- ⭐ **IP 화이트리스트**: nginx/Apache를 통한 IP 제한
- ⭐ **비밀번호 강화**: 더 복잡한 비밀번호 정책

## 설치 검토 사항

### 1. 서버 요구사항
```
최소 사양:
- CPU: 듀얼코어 2GHz 이상
- RAM: 4GB 이상
- Storage: 20GB 여유 공간
- OS: Windows 10/11, Ubuntu 20.04+

권장 사양:
- CPU: 쿼드코어 2.5GHz 이상
- RAM: 8GB 이상
- Storage: SSD 50GB 이상
```

### 2. 네트워크 요구사항
```
- 학교 내부망 연결
- 고정 IP 또는 내부 도메인
- 포트: 80(HTTP), 443(HTTPS), 3001(API)
```

### 3. 예상 부하
```
동시 접속자: 10-20명 (교사)
응답 속도: 평균 100ms 이하
데이터 크기: 연간 약 100MB 이하
```

## 데이터 흐름 및 처리

### 1. 로그인 프로세스
```
1. 교사가 비밀번호 입력
2. 프론트엔드에서 비밀번호 확인 (하드코딩)
3. 세션 정보 sessionStorage에 저장
4. 백엔드 API 접근 가능
```

### 2. 출석 체크 프로세스
```
1. 교사가 학년/공간 선택
2. 백엔드에서 학생 명단 조회 (students.json)
3. 기존 출석 데이터 불러오기 (attendance.json)
4. 교사가 출석 상태 입력
5. 백엔드로 출석 데이터 전송
6. attendance.json 파일에 저장
```

### 3. 데이터 저장 형식
```json
// attendance.json 예시
[
  {
    "studentId": "259",
    "date": "2025-11-06",
    "session": "1",
    "status": "present",
    "room": "창조관 8층 면학실 A",
    "timestamp": "2025-11-06T21:30:00.000Z"
  }
]
```

## 법적 검토 사항

### 1. 개인정보보호법 준수
- ✅ **최소 수집 원칙**: 출석 관리에 필요한 최소 정보만 수집
- ✅ **목적 제한**: 야간자습 출석 관리 목적으로만 사용
- ✅ **내부 보관**: 외부 유출 없이 학교 서버에만 보관
- ✅ **접근 제한**: 교사만 접근 가능

### 2. 데이터 보유 기간
- 권장: 학년도 종료 후 1년
- 필요시 연장 가능
- 자동 삭제 기능 없음 (수동 관리 필요)

### 3. 학생/학부모 동의
- 학칙에 따른 출석 관리는 동의 불필요 (교육 목적)
- 단, 학교 방침에 따라 사전 안내 권장

## 운영 시나리오

### 정상 운영
```
1. 서버 부팅 시 자동 시작 (systemd 또는 PM2)
2. 교사가 스마트폰으로 접속
3. 비밀번호 입력하여 로그인
4. 출석 체크 진행
5. 데이터 자동 저장
6. 매일 자정 자동 백업
```

### 장애 대응
```
1. 서버 다운: 자동 재시작 (systemd restart policy)
2. 네트워크 장애: 접속 불가 알림
3. 데이터 손상: 백업 파일로 복구
4. 포트 충돌: 다른 포트로 변경
```
